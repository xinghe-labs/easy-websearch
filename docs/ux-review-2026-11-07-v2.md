## 二、新发现问题

### P1-1：系统代理让全部抓取型基线引擎集体熄火（新用户第一印象杀手）

- 复现：全新目录（继承 `http_proxy=127.0.0.1:10808`）直接 `npx easy-websearch doctor`
  → **ddg 202 / bing、baidu 反爬页 / sogouweixin 验证码 —— 4 个基线全 FAIL**
- 根因：https 抓取引擎走代理 = 从数据中心出口 IP 抓取 → 被各引擎反爬层识别
- 缓解现状：API 型备援（anysearch/keenable）不受影响照常工作；多引擎融合仍能交付
- 建议：
  1. doctor 在「检测到 HTTPS_PROXY 且 ≥2 个抓取引擎失败」时输出提示行：
     `代理出口可能被反爬拦截 — 尝试 no_proxy=<域名> 或 EASY_WEB_SEARCH_DIRECT=1`
  2. 新增 `--direct` / `EASY_WEB_SEARCH_DIRECT=1`（强制所有引擎绕过代理）
  3. README Troubleshooting 置顶此场景

### P1-2：挂代理的国内用户，最优引擎池组合缺少文档引导

- 实测数据：该人群下 `baidu（直连）+ searxng（境外自建聚合）+ anysearch/keenable` 是
  黄金组合，而 `ddg/bing`（客户端直抓 + 走代理）是最弱两环
- 建议：README 增设「代理用户推荐配置」：`EASY_WEB_SEARCH_ENGINES=searxng,baidu`
  + 明说 ddg/bing 是"无代理用户的保底"

### P2-3：建议新增 `--direct` 全局开关（同 P1-1 建议 2，独立立项）

### P2-4：`npx easy-websearch setup` 是完整的第二上手路径，但 README 没写

- 实测：npm 包内含 SKILL.md 全套，`npx easy-websearch setup --dir ~/.claude/skills`
  一条命令完成安装+验证 —— 对不想装全局包的 npm 用户是零摩擦路径
- 建议：README Quick start 的 npm 行补充这条

### P2-5：skills add 的 GitHub 克隆在国内直连下不稳定

- 实测：同一会话内首次成功、再次失败（`gnutls_handshake() failed`）
- 建议：README 对比表注明「国内用户推荐 npm 路径（不碰 GitHub）」

### P3-6：冷却 10 分钟对瞬时网络抖动偏长

- 实测：searxng 因 NAT 网关瞬时丢连接进冷却，恢复后仍被跳过（需手动清除）
- 建议：首次失败冷却 2 分钟、连续失败递增（1→2→10）；成功即清（已实现）

### P3-7：fetch 对 reader 被拒场景（HTTP 422）可补一句「目标站可能拒绝了 reader」
